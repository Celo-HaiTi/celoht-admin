# CeloHT Admin Production Migration Report

**Date:** 2026-09-07  
**Branch:** `main`  
**Overall status:** NOT PRODUCTION READY

## 1. Executive Summary

The repository was a mock-first Next.js dashboard shell. The initial forensic
inspection found fabricated data directly imported by all dashboard pages,
missing live provider/server boundaries, an incomplete authentication callback,
and audit records that were displayed but not generated by privileged actions.

This migration adds fail-closed production containment, removes the legacy public
mock switches from runtime configuration, adds provider/provenance contracts,
implements a verified native CELO RPC balance adapter, completes the Supabase
magic-link callback, adds append-only audit protections, and adds health and
readiness endpoints. It does not claim that the external CeloHT indexer,
verified deployment metadata, live Supabase project, impact evidence, or
production operations are configured.

## 2. Original Architecture

`Dashboard route -> client dashboard component -> deterministic lib/mock-data generator`

`isMockMode()` controlled only a banner. It did not select a real provider, so a
configured Supabase environment could still render fabricated values.

## 3. New Architecture

`Authenticated request -> server route boundary -> provider contract -> verified source -> provenance-aware result`

Production dashboard routes currently stop at an explicit `UNAVAILABLE` state
until a verified provider is configured. Development fixture imports are moved
behind `app/dashboard/[slug]/development-map.tsx` and are not executed by the
production route.

## 4. Findings

The complete finding register is in [FORENSIC_AUDIT.md](FORENSIC_AUDIT.md). The
most serious findings were direct production fixture imports, silent mock
fallbacks, fabricated treasury/donation/governance/audit values, missing auth
callback, incomplete server RBAC, and absent audit writers. Remediation is
partial; unresolved findings are listed below.

## 7. Database Migrations

- `0004_audit_provenance_hardening.sql` adds audit provenance fields, an
  append-only update/delete trigger, and denies direct authenticated/anonymous
  audit inserts, updates, and deletes.
- **NOT VERIFIED:** Existing migrations have not been applied to a live Supabase
  project from this environment.
- **NOT VERIFIED:** Full RLS integration, storage policies, KYC/evidence access,
  and live role bootstrap have not been tested against Postgres.

## 8. API Endpoints

- `GET /auth/callback`: exchanges a Supabase magic-link code server-side and
  validates internal redirect paths.
- `GET /admin/api/health`: reports non-secret configured dependency status.
- `GET /admin/api/ready`: returns `503` until Supabase, service role, RPC,
  indexer, and fixture-disable configuration are present.

## 9. Authentication Changes

- Removed unauthenticated mock access from middleware.
- Added a server-side Supabase callback and open-redirect protection.
- Dashboard access remains session-gated by middleware.
- **NOT VERIFIED:** MFA, session revocation policy, rate limiting, and a live
  Supabase authentication flow require deployment testing.

## 10. RBAC Changes

The trusted profile role remains the database/RLS source of truth. The audit
writer resolves the role server-side and never accepts a browser-supplied role.
The existing role vocabulary is `director`, `council`, `contributor`, and
`viewer`.

- **NOT VERIFIED:** The requested expanded role matrix and negative tests for
  every sensitive operation are not complete.
- **NOT VERIFIED:** Live RLS behavior has not been exercised against a deployed
  database.

## 11. RLS Changes

The new migration protects `audit_log` from direct authenticated/anonymous
mutation and rejects update/delete through a database trigger. Existing RLS
policies remain in place.

- **REQUIRES INDEPENDENT SECURITY REVIEW:** governance update constraints,
  profile visibility, sensitive evidence/KYC policies, and service-role usage.

## 12. Blockchain Integration

`lib/data/providers/celo.ts` reads native CELO balance from a configured RPC,
validates chain ID and treasury address, and returns block-backed provenance. It
does not calculate USD value without an approved price source and does not sign
transactions.

- **BLOCKED — EXTERNAL DEPENDENCY:** verified treasury address, token contracts,
  deployment metadata, and approved price source are not supplied.
- No private key or browser signing path was added.

## 13. Indexer Integration

Provider contracts include chain, transaction, block, verification, and freshness
fields. Treasury transaction history and all other canonical event-backed
domains remain `UNAVAILABLE` until the official CeloHT indexer endpoint,
authentication, event signatures, confirmations, and reorg policy are provided.

**BLOCKED — EXTERNAL DEPENDENCY.**

## 14. Mock-Data Isolation

- Removed runtime references to `NEXT_PUBLIC_FORCE_MOCK_DATA` and
  `NEXT_PUBLIC_ALLOW_UNAUTHENTICATED_MOCK_MODE`.
- Removed forced mock mode from Docker and CI builds.
- Production route code dynamically loads fixture-backed dashboards only after
  the production branch is excluded.
- Production returns `UNAVAILABLE` rather than a fixture when providers are not
  configured.
- Fixture modules remain under `lib/mock-data/` and require a development/test
  execution context.

## 16. Remaining Risks

- Dashboard domain pages still contain legacy fixture UI implementations for
  development; real provider wiring is incomplete for all domains except native
  CELO balance.
- Donations, governance, agents, education, reforestation, and audit reads are
  not connected to canonical production sources.
- Existing SQL migration layout is still root-level and has not been verified
  against a deployed Supabase project.
- Dependency audit reports `6 high` and `3 critical` vulnerabilities.
- MFA, rate limiting, backups, monitoring, secret rotation, and disaster
  recovery are not verified.

## 17. Production Deployment Requirements

Before deployment, operators must apply reviewed migrations, configure verified
external sources, run security/RLS integration tests, remediate high/critical
dependencies, configure secret management and MFA, and complete an independent
security review. No Celo Mainnet deployment is performed by this repository.
